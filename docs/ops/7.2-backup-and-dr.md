## 1. What must be recoverable

| Asset | Contents | Failure mode if lost |
| --- | --- | --- |
| **MySQL `ims`** | All tenant business data, identity, Flyway history, document/certificate **metadata** | Total product outage |
| **Object store (`ims-private`)** | Person documents, certificates, institute logos (bytes at `institutes/{id}/…`) | Metadata remains but downloads/uploads break |
| **Secrets** | JWT signing key, DB, storage credentials | Auth / storage fail — restore from vault, not from DB dump |

Application images and Angular static assets are rebuilt from git — not part of this backup set.

## 2. RPO / RTO (v1 accepted)

| Target | v1 commitment | Notes |
| --- | --- | --- |
| **RPO** | **≤ 24 hours** | Daily full MySQL dump + daily object sync. Improve later with binlog/PITR and continuous object versioning. |
| **RTO** | **≤ 8 hours** | Includes: provision scratch/prod host, restore MySQL, restore objects, point app config, smoke login + one document download + outstanding list. |

These match [doc 09](../09-deployment-and-operations.md) §5 and are **accepted for v1** pending hosted-platform specifics (managed MySQL / S3).

| Cadence | Action |
| --- | --- |
| Daily | Automated MySQL dump + MinIO/S3 sync to off-host storage |
| Weekly | Retention prune (keep ≥ 7 daily; monthly keep ≥ 30 days) |
| Quarterly | Full restore drill to scratch (record in this folder) |

## 3. Local / docker-compose procedures

### 3.1 Backup MySQL

```powershell
.\scripts\backup\backup-mysql.ps1
# Optional: Docker MySQL on 3307
.\scripts\backup\backup-mysql.ps1 -Port 3307 -User ims -Password ims
```

Writes `backups/mysql/ims-yyyyMMdd-HHmmss.sql` (gitignored).

Uses `mysqldump --single-transaction --routines --triggers` (InnoDB-consistent without long table locks).

### 3.2 Backup MinIO

```powershell
.\scripts\backup\backup-minio.ps1
```

Uses `amazon/aws-cli` against the S3 API (`s3 sync`) into `backups/minio/<stamp>/`.

Requires Docker Desktop and a reachable MinIO (`infra` compose service `minio`).

### 3.3 Restore to scratch (safe drill)

```powershell
.\scripts\backup\run-restore-drill.ps1
```

Or stepwise:

```powershell
$dump = .\scripts\backup\backup-mysql.ps1
$dir  = .\scripts\backup\backup-minio.ps1
.\scripts\backup\restore-mysql-scratch.ps1 -DumpFile $dump
.\scripts\backup\restore-minio-scratch.ps1 -BackupDir $dir
```

| Scratch | Ports | Purpose |
| --- | --- | --- |
| `ims-mysql-scratch` | **3308** | Prove dump restores; live `3306` untouched |
| `ims-minio-scratch` | **9100** / **9101** | Prove object sync restores; live `9000` untouched |

Default: containers removed after verification. Pass `-KeepContainer` to inspect.

### 3.4 Restore into a real environment (ops)

1. Stop API writers (or freeze traffic at gateway).  
2. Restore MySQL dump into the target empty database (`mysql < dump.sql`).  
3. Sync objects into the target bucket (same keys).  
4. Confirm secrets (`IMS_SECURITY_JWT_SECRET`, DB, `IMS_STORAGE_*`) — **do not** copy prod JWT into a shared scratch that others can read.  
5. Start API with Flyway `validate` (dump already includes schema; do not re-baseline).  
6. Smoke: login → student search → outstanding → open one document/certificate download.

## 4. Production guidance (hosted)

| Asset | Recommended | Retention |
| --- | --- | --- |
| MySQL | Provider automated backup + optional PITR/binlog | ≥ 30 days |
| Objects | Bucket versioning + cross-region/replication copy | ≥ 30 days |
| Secrets | Vault / cloud secret manager backup policy | Per org |

Encrypt backups at rest (disk/object SSE or encrypted dump archive). Restrict who can read backup buckets.

Alert when the daily backup job fails (doc 09 observability).

---

## 5. Consistency notes

- MySQL dump and MinIO sync are **not** a single distributed snapshot. A document uploaded during the gap may appear as metadata without bytes (or vice versa). Acceptable for v1 RPO 24h; mitigate by taking MinIO sync immediately after MySQL dump (scripts already ordered that way in the drill).  
- Soft-deleted document metadata may still reference keys; lifecycle on the bucket is TBD (doc 08).  
- Jaeger traces are ephemeral — not backed up.
