## 1. Indexes verified

| Query / use case | Index | Migration |
| --- | --- | --- |
| Login by institute + username | `uk_users_institute_username (institute_id, username)` | V3 |
| Outstanding list `status` + `outstanding_amount > 0` | `idx_fee_accounts_outstanding (institute_id, status, outstanding_amount)` | **V26** |
| Student list/filter by status + soft-delete | `idx_students_status_deleted (institute_id, status, deleted_at)` | **V26** |
| Student code lookup | `uk_student_code (institute_id, student_code)` | V4 |
| Student name prefix (non-leading-wildcard) | `idx_students_institute_name` | V4 |
| Finance reports (aging/collections) | `idx_invoices_due_status`, `idx_payments_paid_status`, … | V18 |

**Note:** `GET /students?q=…` uses leading-wildcard `LIKE %q%` — remains a tenant-scoped scan; acceptable for v1 institute sizes. Exact code lookup uses the unique key.

Confirmed present in local `information_schema` after Flyway V26.
