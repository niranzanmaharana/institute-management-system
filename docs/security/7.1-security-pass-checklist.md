## 1. OWASP-oriented control review

| # | Control (mapped) | Status | Notes |
| --- | --- | --- | --- |
| A01 | Broken access control | Pass (with fixes) | `@PreAuthorize` on controllers; tenant scoping; enrollment list/get/cancel now include `enrollment:write`; capacity override still ADMIN-only in service; tenant-probes restricted to ADMIN / PLATFORM_ADMIN |
| A02 | Cryptographic failures | Pass | BCrypt passwords; JWT HMAC ≥32 bytes; refresh tokens SHA-256 at rest; prod profile rejects default JWT secret |
| A03 | Injection | Pass | JPA / parameterized queries; validated request bodies |
| A04 | Insecure design | Pass | Multi-tenant from day one (ADR 0004); PLATFORM_ADMIN not silent superuser on institute APIs |
| A05 | Security misconfiguration | Pass (dev defaults documented) | OpenAPI/Swagger `permitAll` only when `ims.security.expose-openapi=true`; disabled in `prod` profile; actuator limited to health/info |
| A06 | Vulnerable components | Pass* | Dependabot weekly; Maven `dependency-check` profile (`failBuildOnCVSS=9`); UI prod `npm audit --omit=dev` = 0; see [7.1-dependency-scan.md](./7.1-dependency-scan.md) |
| A07 | Identification & auth failures | Pass | Generic login errors; login_audit; account lockout after N failures (`ims.security.max-failed-logins` / `lock-minutes`); gateway rate limit on login **and** refresh |
| A08 | Software & data integrity | Pass | Flyway migrations; no unsigned plugin installs in build |
| A09 | Security logging failures | Pass | Login success/fail audits; correlation ids on API errors; PII (email/phone) not logged at INFO on people create paths |
| A10 | SSRF | N/A / low | No user-controlled server-side URL fetch in v1 API surface |

\*Re-run OWASP Dependency-Check in CI with an NVD API key before each release.

## 2. CSRF / session strategy (documented)

| Choice | v1 decision |
| --- | --- |
| Access token | Bearer JWT in `Authorization` header |
| Refresh token | JSON body; stored hashed; UI keeps tokens in `localStorage` |
| CSRF | **Disabled** — no cookie-based session for API auth |
| Future cookie refresh | Must add CSRF (double-submit or SameSite+prefix) before enabling HttpOnly cookie refresh |
| XSS risk | Treat UI XSS as critical; do not move refresh to cookies without CSRF design |

## 3. Rate limits reviewed

| Endpoint | Limit | Store | Prod note |
| --- | --- | --- | --- |
| `POST /api/v1/auth/login` | 20 / 60s / client IP | In-memory (gateway) | Use Redis (or edge WAF) for multi-instance |
| `POST /api/v1/auth/refresh` | 20 / 60s / client IP | Same | Same |
| Direct `:8080` bypass | Not rate-limited | — | Edge must only expose gateway |

Config: `ims.gateway.login-rate-limit.*`

## 6. Permission matrix spot checks

| Area | Result |
| --- | --- |
| Students / faculty / admissions / fees / attendance / exams / imports / reports | `@PreAuthorize` present |
| Enrollment create | `course:write` \| `enrollment:write` |
