## 2. Policy

1. Code annotations (springdoc) are the source; **commit** the exported JSON at `docs/api/openapi.json`.
2. PRs that change the contract are compared to the base branch with **oasdiff**.
3. **Breaking** changes fail CI unless `info.version` gets a **major** bump (`1.x` → `2.x`). While still below `1.0.0`, a **minor** bump (`0.1.0` → `0.2.0`) is the breaking channel (oasdiff semver rules).
4. Bump the version in both:
   - `ims-backend/ims-api/.../OpenApiConfig.java` (`.info().version(...)`)
   - regenerated `docs/api/openapi.json`

Non-breaking additive changes may keep the same version (or bump patch/minor as you prefer); oasdiff only requires a bump when the change is breaking.

---

## 3. Developer workflow

```powershell
# After API surface changes, with ims-api on :8080:
.\scripts\openapi\export-openapi.ps1

# If the change is breaking, bump OpenApiConfig version first, re-export, commit both.

# Optional local breaking check vs previous file:
.\scripts\openapi\check-breaking.ps1 -Base docs/api/openapi.json -Revision path\to\new.json

# Prove the gate logic:
.\scripts\openapi\verify-gate.ps1
```

CI also runs `OpenApiContractIT` so forgetting to export fails the build.
